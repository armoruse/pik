# 全球未滿 5 人尋菇篩選器（開發中）

目前需求：尋找全球已取得掃描紀錄中，0～4 人的大型元素菇與巨大活動菇，顯示座標、當地日期時間及台灣時間，供使用者自行選擇前往。也保留附近模式。

## 已完成

讀取 gpsGo 2.1.1-debug 本機掃描儲存格式：`gpsgo_scan_results.xml` 的 `results_v1`。用 gpsGo 正常掃描結果篩選，不存取遊戲內部資料。這是電腦端工具，尚未整合成手機 App 按鈕，也不會自行開啟或操作 gpsGo 掃描。

- 預設附近半徑 1000 公尺；中心必須由當下遊戲位置確認後提供，不能使用模擬器預設地點。
- 人數只接受整數 0～4。缺值不視為 0。
- 只接受座標來源欄位為 `GEO_INTENT` 且有觀察 `id` 的紀錄；保留 observation、place、session 識別碼。這是本機資料欄位核對，仍需與遊戲現場比對；缺來源的舊紀錄不會直接變成可用座標。
- LARGE 配合 FIRE / WATER / CRYSTAL / ELECTRIC / POISON。
- GIANT 配合 UNKNOWN 與已核對的完整活動名稱。已核對巨大萬聖節蘑菇與英文名稱；未知活動需新增明確分類，不能因 GIANT 就當成活動菇。
- 必須 CONFIRMED，掃描與確認時間均不超過 5 分鐘且不得在未來。這是保守的本工具門檻，不是遊戲規則。
- 同地點採最新觀察；新觀察滿人、消失或人數不明會排除舊的空位紀錄。
- 預設單次讀取；`--watch` 每 10 秒重新讀取既有紀錄並重新判斷時效。這不是每 10 秒重新掃描遊戲。
- 讀取失敗會清除本次輸出的舊候選，不會誤把舊結果標成仍可參加。
- 缺少時區套件或初始化失敗也會清除舊候選。單次執行失敗回傳結束碼 1；成功回傳 0（沒有候選也屬成功）。`--watch` 遇到資料或套件讀取錯誤仍會每 10 秒重試，這不會重新掃描遊戲。

官方活動名稱來源：https://pikminbloom.com/zh_hant/news/oct26-halloweenevent （2026-10-21 查核）

## 執行

```sh
python3 finder.py --adb /完整路徑/adb --serial emulator-5582 --center 緯度 經度 --radius 1000 --output /輸出目錄 --watch
```

也可使用 `--input 掃描紀錄.json` 取代 `--serial`。不支援未授權的第三方座標 API；座標與人數必須來自正常的掃描或匯出資料。

`run-as` 僅適用目前手機既有的 debug gpsGo。一般 release App 不一定允許讀取；遇到拒絕應改用 App 正常匯出，而非繞過。

## 全球座標與當地日期（2026-10-22 更新）

最新需求改為全球範圍，使用 `--worldwide`，不必提供中心。這代表篩選所有已取得的 gpsGo 掃描紀錄，**不是程式已有全球即時蘑菇資料，也不是自動全球移動掃描**。

新增 `local_time.py` 以座標查 IANA 時區、`zoneinfo` 換算當地及台灣日期時間，支援夏令時間、半小時／45 分鐘時差和換日線。套件版本鎖定於 requirements.txt，使用本專案 work/mushroom-venv。

輸出「未滿5人蘑菇.json」、「未滿5人蘑菇.md」、「尋菇候選與當地時間.html」。HTML 當地時間每秒更新，紀錄過期後停用複製按鈕；頁面每 15 秒自動載入最新輸出；需保持 --watch 執行。時鐘依電腦現在時間，座標時區與遊戲帳號免費次數是不同資訊。

官方說明為每日 3 次免費挑戰，第四次起或加入已有 5 人的菇須用券。官方頁面未足以證明跨時區移動如何影響個別帳號的重置，因此此工具永遠不會僅根據當地換日標記「免費」；也不會按參戰或使用蘑菇券。

## 續掃資訊與手機座標橋接（2026-10-24）

`scan_progress` 現在附未完成格、失敗／中斷格的索引，以及原中心、半徑與畫面尺寸。索引由 0 起，只代表掃描工作格，不能當成蘑菇座標。已完成格不會重新列入；丟棄的掃描不提供續掃工作。儲存狀態 RUNNING 也不代表服務活著，必須回到 gpsGo 確認。只對已核對的 detector 2／calibration 1 檢查點提供續掃條件，版本或資料缺失時需重新校準。

正常入口是「設定 → 已保存的掃描 → 續掃未完成格／重試失敗格」。原中心、縮放、北向上與畫面尺寸都需恢復，再重新校準及取得螢幕擷取授權。此版只輸出條件與工作清單，沒有自動確認校準或操控全球巡掃。

新增 `手機座標回報.json`（JSON 陣列，最多 200 筆）和 HTML「複製手機座標回報 JSON」。它對應 `rog3/java/.../RogResources.java` 的匯入契約：

- 菇種轉為 `LARGE_ELEMENTAL`／`GIANT_EVENT`，保留座標、IANA 時區、人數、觀察 ID、地點 ID、掃描 ID 與來源。
- `observed_at`／`expires_at` 使用 UTC；期限沿用 5 分鐘，匯入不會重新開始計時或延長成 15 分鐘。
- 缺時區、缺來源、過期或人數不明不匯出；讀取失敗重寫為空陣列，HTML 到期後停用複製。
- 目標是支援此格式的 ROG 建置；尚未確認手機上 `rog1.0.2` 有對應入口，也沒有在實體手機完成匯入或探險驗證。JSON 本身不是已派出探險的證據。
